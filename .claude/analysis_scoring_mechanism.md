## 二、打分机制推测（基于评测反馈）

### 2.1 适配度（Adaptability）评分标准（推测）

通过分析所有"认知摩擦点"和"最佳改进方针"，我推测适配度评分机制如下：

#### **核心评分维度：**

1. **术语密度惩罚（-0.25至-0.5分）**
   - 检测点：首次出现的学术术语是否有即时定义
   - 典型案例：
     - ❌ "Heuristic" 直接出现 → 扣分（實現人工智慧1，适配度4.25）
     - ❌ "Marginal Thinking" 无定义 → 扣分（函數建模2，适配度4.2）
     - ✅ "Inference Engine" + "reasoning system" → 不扣分

2. **数学符号突然性惩罚（-0.25至-0.5分）**
   - 检测点：LaTeX公式、求和符号、希腊字母出现前是否有缓冲
   - 典型案例：
     - ❌ Ridge/Lasso公式突然出现 [04:40] → 扣分（迴歸1，适配度4.75但仍被标记）
     - ❌ MSE公式的求和符号 [03:49] → 扣分（迴歸2，适配度4.25）
     - ❌ 染色体数字2n=63突然出现 [04:10] → 扣分（進化1，适配度4.0）

3. **认知跳跃惩罚（-0.25至-0.5分）**
   - 检测点：从概念到公式、从简单到复杂的过渡是否平滑
   - 典型案例：
     - ❌ "从概念直接跳到公式" → 扣分
     - ✅ "概念 → 类比 → 简化公式 → 完整公式" → 不扣分

4. **消化时间缺失（-0.25分）**
   - 检测点：关键概念后是否有"pause and think"提示
   - 所有视频都缺少这个，但只有部分被明确扣分

#### **评分公式推测：**
```
适配度基础分 = 5.0
最终适配度 = 基础分 - 术语密度惩罚 - 数学符号惩罚 - 认知跳跃惩罚 - 消化时间惩罚
```

**验证案例：**
- **進化（1）**：4.8正确性 + 4.75逻辑 → 但适配度4.0
  - 原因：染色体数字2n=63突然出现（-0.5），缺乏术语定义（-0.25），无消化时间（-0.25）
  - 计算：5.0 - 0.5 - 0.25 - 0.25 = 4.0 ✅

- **函數建模（2）**：5.0正确性 + 5.0逻辑 → 但适配度4.2
  - 原因："Marginal"术语无定义（-0.5），公式跳跃（-0.3）
  - 计算：5.0 - 0.5 - 0.3 = 4.2 ✅

- **用於解釋的迴歸（1）**：4.6正确性 + 4.5逻辑 → 适配度4.75（最高）
  - 原因：使用了商业类比（"studying vs exam"），只有一个摩擦点（Ridge/Lasso公式）
  - 计算：5.0 - 0.25 = 4.75 ✅

## 三、v6失败原因深度分析

### 3.1 v6的核心修改（dd34087, 6a696e0）

根据git diff统计：
- 13个文件修改
- +487行，-301行
- 主要修改：`src/overview_scene.py`（大幅重构）

### 3.2 v6的致命错误

#### **错误1：过度简化Overview（违反学生预期）**

**v5版本（正确）：**
```python
OVERVIEW_INTRO_LINE = "This video will be divided into the following parts"
# 输出：5-12项详细章节列表
# 示例："the first part, Basic Concepts"
#       "the second part, Core Principles"
```

**v6版本（错误）：**
```python
OVERVIEW_INTRO_LINE = "Today's roadmap"  # ❌ 过于口语化
# 输出：3-6项"高层学习路径"
# 示例："Start from the core problem"
#       "See why the first idea helps"
```

**为什么这是错误的？**
1. **学生需要具体的章节预期**，而不是抽象的"学习路径"
2. 评测反馈明确指出：学生依赖Overview来预知"what will be covered"
3. "Today's roadmap"过于口语化，缺乏学术感（评测偏好学术化表达）

#### **错误2：移除序号结构（破坏逻辑连贯性）**

**v5版本（正确）：**
```python
# 保留"the Xth part"结构
"the first part, Basic Concepts"
"the second part, Core Principles"
```

**v6版本（错误）：**
```python
# 移除序号，改为因果关系
"Start from the core problem"  # ❌ 无法对应后续章节
"See why the first idea helps"
```

**为什么这是错误的？**
- 学生在观看过程中无法将Overview与实际章节对应
- 破坏了"Advance Organizer"的核心功能：提供清晰的导航地图

#### **错误3：同时修改多个模块（风险叠加）**

v6同时修改了：
- `src/overview_scene.py`（核心逻辑）
- `src/audio_steps.py`（TTS扩展）
- `prompts/stage2.py`（Storyboard生成）
- `prompts/user_profile.py`（用户配置）

**结果：**
- 无法定位具体哪个修改导致了不稳定
- 逻辑和正确率都受到影响

## 四、优化方案（基于v5，避免v6错误）

### 4.1 核心策略：增量式、低风险优化

**原则：**
1. ✅ 保留v5的稳定架构（Overview、逻辑流程）
2. ✅ 只在边缘增加适配性功能
3. ✅ 每次只优化1-2个明确问题点
4. ❌ 不修改已获得"exceptional"评价的部分

### 4.2 具体优化方案

#### **方案A：术语即时定义系统（优先级：高）**

**目标：** 在术语首次出现时，自动插入简短定义

**实施位置：** `src/audio_steps.py` 的 `expand_screen_text_to_spoken_script()`

**实施方法：**
1. 建立术语词典（按学科分类）
2. 检测screen_text中的术语
3. 在spoken_script中自动添加括号定义

**术语词典示例：**
```python
TERMINOLOGY_DICT = {
    "biology": {
        "heuristic": "rule-driven",
        "inference engine": "reasoning system",
        "translocation": "two-way transport",
        "lignin": "rigid cell wall material",
    },
    "math": {
        "marginal": "step-by-step change",
        "tangent line": "flat line at the peak",
        "vertex": "highest or lowest point",
    },
    "statistics": {
        "MSE": "Mean Squared Error, the average of squared differences",
        "Ridge": "a penalty method that shrinks coefficients",
        "Lasso": "a penalty method that can zero out coefficients",
    }
}
```

**预期效果：**
- 术语密度惩罚：-0.5 → -0.1（减少0.4分损失）
- 适配度提升：4.0-4.2 → 4.4-4.6

---

#### **方案B：公式引入缓冲机制（优先级：高）**

**目标：** 在复杂公式出现前，增加过渡句

**实施位置：**
1. `prompts/stage2.py` - 增加公式检测和过渡句生成
2. `src/audio_steps.py` - 在TTS生成时增加停顿

**实施方法：**
1. 在Stage 2生成storyboard时，检测LaTeX公式
2. 当检测到公式时，在前一个lecture_line添加过渡提示
3. 在TTS生成时，为公式行增加0.5-1秒的前置停顿

**过渡句模板：**
```python
FORMULA_TRANSITION_TEMPLATES = [
    "Let's break this down step by step",
    "Now, here's the mathematical form",
    "The formula looks like this",
    "Mathematically, we can express this as",
]
```

**预期效果：**
- 数学符号惩罚：-0.5 → -0.2（减少0.3分损失）
- 适配度提升：4.0-4.2 → 4.3-4.5

---

#### **方案C：认知检查点插入（优先级：中）**

**目标：** 在关键概念后自动插入"pause and think"提示

**实施位置：** `src/agent.py` - 利用现有的`zpd_check_line_index`字段

**实施方法：**
1. 识别zpd_check_line（ZPD检查点）
2. 在这些行的spoken_script中添加：
   - "Take a moment to process this"
   - "Let's pause here - make sure this makes sense"
3. 在视频中显示5秒的"💭 Concept Check"图标

**预期效果：**
- 消化时间惩罚：-0.25 → 0（减少0.25分损失）
- 适配度提升：4.0-4.2 → 4.25-4.45

---

#### **方案D：年级自适应简化增强（优先级：中）**

**目标：** 扩展术语简化词典，覆盖更多学科和年级

**当前v5已有：**
- `expand_screen_text_to_spoken_script()`中已有grade_level判断
- 已有middle_school的术语简化示例

**需要增强：**
1. 扩展术语简化词典（目前只有少数示例）
2. 为high_school和ap_college建立不同策略
3. 在公式引入时，根据年级调整解释深度

**预期效果：**
- 术语密度惩罚：-0.5 → -0.15（减少0.35分损失）
- 适配度提升：4.0-4.2 → 4.35-4.55

## 六、风险控制（从v6失败中学到的教训）

### 6.1 禁止事项

❌ **不要大幅修改已经获得"exceptional"评价的部分**
- 如Signaling（视觉引导）
- 如视觉质量
- 如节奏控制

❌ **不要为了"创新"而牺牲清晰度**
- 如Overview的过度简化
- 如移除序号结构

❌ **不要同时修改多个核心模块**
- v6同时改了13个文件，导致无法定位问题

### 6.2 应该做的

✅ **采用增量式改进**
- 每次只优化1-2个明确的问题点

✅ **保留v5的稳定架构**
- 只在边缘增加适配性功能

✅ **充分测试后再推进**
- Phase 1 → 测试 → Phase 2 → 测试 → Phase 3

## 七、总结

### 7.1 核心洞察

1. **适配度是唯一短板**：正确性和逻辑已经优秀，只需提升适配度
2. **打分机制是惩罚制**：基础分5.0，每个摩擦点扣0.25-0.5分
3. **v6失败的根本原因**：过度创新，破坏了学生的认知预期

### 7.2 优化路径

```
v5（稳定基线）
  ↓
Phase 1：术语定义 + 年级自适应（低风险）
  ↓
测试验证（确保稳定性）
  ↓
Phase 2：公式缓冲 + 认知检查点（中等风险）
  ↓
最终验证（适配度4.5+）
```

### 7.3 预期结果

- **適配度**：4.0-4.2 → 4.5+（提升0.3-0.5分）
- **總分**：4.42-4.62 → 4.65-4.80（提升0.2-0.3分）
- **穩定性**：保持v5的正確性和邏輯流暢優勢
